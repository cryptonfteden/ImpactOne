# Product Experience Architecture — Phase PRODUCT-001

## Mission

Transform ImpactOne from a collection of intelligent screens into a coherent
daily decision experience. No new AI engines, no visual redesign, no
replaced functionality — only better prioritization, flow, and product
consistency over the intelligence that already exists.

## Core principle

The user should never wonder "what should I look at first?" Two new
canonical services answer that automatically:

- **Attention Engine** (`backend/services/attentionEngine/attentionEngine.js`)
  — a deterministic 0-100 score + plain-language explanation for any real
  Claim, feed item, or symbol.
- **Morning Brief** (`backend/services/morningBrief/morningBriefService.js`)
  — the day's 5-8 highest-Attention-Score items, generated by ranking real
  Claims and real portfolio changes through the Attention Engine.

Every screen either calls one of these two services directly (via a thin
controller) or reads an `attentionScore`/`attentionExplanation` field that a
controller has already attached to real data on the way out. No screen
computes its own priority ranking from scratch.

## Why this required new routes, not new intelligence

The mission is explicit: no new AI engines. Both new services are pure
prioritization/aggregation logic over data that already exists (Claims,
Options Signals, Market Sentiment, real portfolio state) — they generate no
new beliefs, evidence, or forecasts. They answer "what matters and in what
order," never "what should the platform believe."

## Layering

```
Screen (React) — reorders/labels only, never computes a score
   │
   ▼
services/api/*Api.js (morningBriefApi, existing claimsApi, etc.)
   │
   ▼  HTTP
backend/routes/*Routes.js
   │
   ▼
backend/controllers/*Controller.js
   │  — orchestrates: fetch real data (claims/feed/portfolio) via existing
   │    canonical services, then call attentionEngine to score it
   ▼
backend/services/attentionEngine/attentionEngine.js  (pure, deterministic)
backend/services/morningBrief/morningBriefService.js (composes claims +
   portfolio deltas, ranks via attentionEngine, returns top 5-8)
```

## What changed, by screen

| Screen | Primary question it must answer | What changed |
|---|---|---|
| Mission Control | "What matters today?" | New required top-of-fold block: Today's Brief, Top Risks, Top Opportunities, Portfolio Changes, Claims That Changed Overnight — nothing else appears above it |
| Daily Feed (News) | "What changed?" | Every item now shows a real Attention Score, real affected holdings, and real portfolio relevance; an item with none of that says "No meaningful impact detected." |
| Portfolio Workspace | "How does this affect me?" | Two new sections lead the screen: "What Changed Since Yesterday", then "Why This Affects You" (Why → Evidence → Counter Evidence → Potential Scenarios per Claim) — recommendations no longer shown first |
| Watchlist | "What deserves attention?" | Ranked by each symbol's real max Attention Score (aggregated from its Claims), not by price movement |
| Symbol Page | "What does the platform currently believe?" | New first section: "Why This Symbol Matters Today" (the top Claim's belief + real Attention Score/explanation); everything else becomes supporting context underneath |
| AI Analysis | "Explain everything." | Claims-Based Analysis section reordered to: Executive Summary, Why this matters, Evidence, Counter evidence, Portfolio impact, Possible outcomes, Confidence, Unknowns, Things to monitor next |

## Honesty guarantees

- Attention Engine never fabricates a missing input as 0 — absent factors
  are excluded and remaining weights renormalized, so an item is judged only
  on what's real about it.
- Morning Brief never pads to reach 5 items; a quiet day is honestly a
  shorter (or empty) brief.
- News's "no meaningful impact" state fires only when an item genuinely has
  no affected assets, no held position, and no overlapping Claim — never
  used as a catch-all for "we don't know."
- Every reordering in this phase reuses real, already-existing data
  (Claims, `getPerformanceDelta`, `importanceScore`) — no new fields were
  invented to fill the new section labels (e.g., "Unknowns" reuses the real
  Claim `assumptions` field; "Things to monitor next" reuses
  `invalidationConditions`).
