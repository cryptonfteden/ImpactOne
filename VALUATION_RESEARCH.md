## 1. What this engine needs, and what already exists in this codebase

Unlike the Options Agent (which had zero pre-existing data plumbing), the Valuation Agent has a real, if underused, head start:

- **`finnhubService.js` already calls `GET /stock/metric?metric=all`** (confirmed live in this codebase's own `getStockData()` function) — today it extracts only `peTTM`/`peAnnual` and 52-week high/low from that response, discarding the rest. Finnhub's basic-financials bundle is documented (per Finnhub's own API) to return a much broader set of per-share and per-ratio metrics beyond P/E — **this needs to be re-confirmed field-by-field against Finnhub's live docs before implementation** (a direct doc fetch attempted during this research did not return usable content), but the architectural fact that stands regardless of exact field names is important: **this platform is already paying for and calling an endpoint that likely contains several of the ratios this mission asks about, and is throwing most of the response away.** The first, cheapest step for an MVP is auditing that existing response shape, not adding a new vendor.
- **`backend/services/alphaVantageService.js` already exists** and is wired to a real controller (`marketController.js`'s `getMarketOverview`), gated on `ALPHA_VANTAGE_API_KEY` (present as an empty placeholder in `.env`/`.env.example` — code path real, key value not currently set in this environment). Alpha Vantage's real, well-documented `OVERVIEW` function (a different `functionName` than the `TIME_SERIES_DAILY` default this service currently always calls) returns company fundamentals including `PERatio`, `ForwardPE`, `PEGRatio`, `PriceToBookRatio`, `PriceToSalesRatioTTM`, `EVToEBITDA`, `ReturnOnEquityTTM`, and more — **if this exact function name/field set still holds on Alpha Vantage's current API (not independently re-verified live this session, should be confirmed before implementation), this is a second already-half-wired vendor path requiring only a parameter change and a real API key, not new integration code.**
- **⚠️ Important discovered anti-pattern, worth flagging before any valuation-agent code is written:** `alphaVantageService.js`'s no-key fallback path returns **hardcoded fake OHLC data** (`{"2024-01-01": {open:100, high:104, low:99, close:102, volume:1000}}`) with **no `source:"fallback"` or similar disclosure label** — unlike `altDataService.js`'s `fallbackCot()`, which correctly tags fallback data as such. This is a real, live, undisclosed-fabrication risk already present in this codebase's Alpha Vantage path today. **The Valuation Agent must not reuse this specific function's fallback behavior as-is** — any valuation data sourced through Alpha Vantage must go through a new, honestly-labeled path (returning `null`/`insufficientData`, per this whole engagement's established discipline) rather than this existing silent-fake-data pattern.
- **`profileData.finnhubIndustry`** (confirmed live in `finnhubService.js`) is this codebase's existing sector/industry classification field — already fetched for every symbol via the same Finnhub profile call the Valuation Agent would need anyway for its own baseline company data. **Sector normalization (§9 below) should reuse this field directly rather than introducing a second classification taxonomy (e.g., GICS) requiring a new mapping table.**
- **`canonicalVerdict.js`'s `FORBIDDEN_COMMITTEE_KEYS` denylist governance** (already enforced across 5 other engines: Committee, Options Agent, Sentiment Engine, Intelligence Bus, Claim Layer) applies here without exception: the Valuation Agent must never emit `action`/`decision`/`verdict`/`recommendation`. This has a **direct, important naming consequence for this mission's own requested "Buy Zone"/"Strong Buy Zone" terminology** — addressed explicitly in `FAIR_VALUE_METHODOLOGY.md` §4.

## 2. P/E (Price/Earnings)

**Formula:** `P/E = Price / EPS`, most commonly trailing-twelve-months (TTM) EPS. `EPS = Net Income (attributable to common shareholders) / Diluted Weighted-Average Shares Outstanding`.

- **Strength:** the most widely understood valuation multiple; directly comparable to the market's own historical average and to a "cheap vs. bond yields" framing via its inverse (earnings yield = 1/P/E).
- **Weakness:** meaningless/misleading for negative or near-zero earnings (§8 handles this explicitly); sensitive to one-time/non-recurring items unless "adjusted"/"normalized" EPS is used; not directly comparable across sectors with structurally different margin profiles without sector normalization (§9).
- **Variant to compute alongside it:** both **GAAP EPS-based P/E** and, where available, a **non-GAAP/adjusted EPS-based P/E** — disclose both rather than picking one silently, since companies' own adjusted-EPS definitions vary and can be self-servingly generous; this platform's own honesty discipline argues for showing the GAAP figure as the primary source of truth and the adjusted figure as a clearly labeled secondary view.

## 3. Forward P/E

**Formula:** `Forward P/E = Price / Forward EPS`, where Forward EPS is the consensus analyst estimate for the next fiscal year (or next-twelve-months, NTM).

- **Strength:** more forward-looking than trailing P/E; the standard metric professional equity analysts actually lead with.
- **Weakness:** entirely dependent on the quality/availability of consensus estimates — a real, non-trivial data-sourcing requirement distinct from trailing fundamentals (most free/basic-tier vendors provide trailing data readily but gate forward estimates behind a higher tier, since estimates are a licensed, analyst-sourced product, not a raw filed fact). **This is the single ratio in this mission's list most likely to require a paid/professional-tier data source even for an MVP** — flagged explicitly in §10's data-source recommendation.
- Requires the same negative-earnings handling as trailing P/E (§8), applied to the *forward* estimate rather than the trailing actual.

## 4. PEG (Price/Earnings-to-Growth)

**Formula:** `PEG = P/E ÷ Expected EPS Growth Rate (%, expressed as a plain number, e.g. "20" for 20%)`. The classic Peter Lynch heuristic: a PEG near 1 suggests the market is pricing the stock's growth roughly fairly; well below 1 suggests the stock may be cheap relative to its growth; well above 1 suggests the market may be paying a premium for growth already.

- **Growth-rate input is the critical, easy-to-get-wrong choice**: options include (a) next-year consensus EPS growth, (b) a 3-5-year consensus long-term growth estimate, (c) trailing historical growth (backward-looking, weaker signal for a forward-looking ratio). **Recommend the 3-5-year consensus long-term growth rate where available** (closer to Lynch's original intent and less noisy than a single next-year estimate), falling back honestly to next-year growth with a disclosed `growthHorizonUsed` field when 3-5yr consensus isn't available, rather than silently mixing horizons across different companies in the same comparison.
- **Compounds the same data-sourcing constraint as Forward P/E** (§3) — needs a real consensus-growth-estimate provider, not just trailing filed financials.
- **Undefined/misleading for negative P/E or negative/near-zero growth** — must be explicitly suppressed (return `null`) rather than computed into a nonsensical (e.g. doubly-negative-cancels-to-positive) number, a well-known real screener bug class. Same discipline as §8.

## 5. EV/EBITDA (Enterprise Value / EBITDA)

**Formula:** `EV = Market Capitalization + Total Debt + Preferred Equity + Minority Interest − Cash & Cash Equivalents`. `EBITDA = Operating Income + Depreciation & Amortization` (equivalently, Net Income + Interest + Taxes + D&A).

- **Strength:** capital-structure-neutral — unlike P/E (which only reflects the equity holder's claim and is distorted by leverage), EV/EBITDA lets you compare a heavily-indebted company to a debt-free one on a like-for-like basis, and works even when net income is negative due to high interest expense (a leveraged company can have negative EPS but healthy EBITDA). This makes it the single most useful multiple in this list for capital-intensive or leveraged sectors (industrials, telecom, private-equity-style rollups) — and a valuable secondary signal even for names where P/E is usable, precisely because it isolates operating performance from financing decisions.
- **Weakness:** ignores capital expenditure requirements entirely — a capital-intensive business can show attractive EBITDA while consuming enormous cash in capex, which is exactly why Free Cash Flow Yield (§7) is recommended as a companion metric, never a substitute.
- **Requires real balance-sheet data** (total debt, cash, minority interest) beyond just an income-statement/EPS figure — a materially heavier data requirement than P/E, relevant to the data-source tiering in §10.

## 6. Price/Sales (P/S)

**Formula:** `P/S = Market Capitalization / Trailing-Twelve-Month Revenue` (equivalently, Price per share ÷ Revenue per share).

- **Strength:** revenue is far less prone to manipulation or being negative than earnings — this is the single most important reason to include P/S in this suite: **it remains computable and meaningful for unprofitable/pre-profit growth companies where P/E and PEG are structurally unusable** (§8's central data-integrity concern). This makes P/S the natural primary multiple for high-growth, currently-unprofitable names.
- **Weakness:** says nothing about margin/profitability — two companies with identical P/S can have wildly different actual economics if one has 40% margins and the other has 5%. **Must never be presented alone as a "cheap" signal without at least a qualitative profitability/ROIC cross-check (§7's companion role).**

## 7. Free Cash Flow Yield

**Formula:** `FCF = Cash Flow from Operations − Capital Expenditures`. `FCF Yield = FCF per Share / Price` (equivalently `FCF / Market Capitalization`), expressed as a percentage — framed as a **yield** (higher = cheaper) rather than a multiple (lower = cheaper), which is deliberately more intuitive for direct comparison against a risk-free rate or a company's own cost of capital.

- **Strength:** cash flow is the hardest of these figures to manipulate via accounting choices (unlike EPS, which is sensitive to depreciation policy, one-time charges, share-based comp treatment) — many practitioners consider FCF yield the single most trustworthy "is this cheap" signal of the group.
- **Important nuance for §8 (negative earnings):** a company can have **negative GAAP earnings while still generating positive free cash flow** (common for businesses with heavy non-cash depreciation/amortization, or heavy stock-based-compensation expense that depresses GAAP net income without consuming cash) — this makes FCF Yield the single best fallback signal specifically for negative-earnings companies, ahead of even P/S, whenever it is computable and positive.
- An **EV-based variant** (`FCF / Enterprise Value`, rather than `/ Market Cap`) is the capital-structure-neutral counterpart, exactly analogous to EV/EBITDA vs. P/E — recommend computing both and disclosing which is used where, following the same dual-disclosure principle as §2's GAAP-vs-adjusted P/E.

## 8. ROIC (Return on Invested Capital)

**Formula:** `ROIC = NOPAT / Invested Capital`. `NOPAT (Net Operating Profit After Tax) = Operating Income × (1 − effective tax rate)`. `Invested Capital = Total Debt + Total Equity − Cash & Cash Equivalents` (a common, simplified formulation; more rigorous versions net out non-operating assets too).

- **This is not a valuation multiple at all — it is a capital-efficiency/quality metric**, and its role in this suite is explicitly **as a gate against value traps**, not as a 10th price ratio to average in. A stock can look statistically cheap on every multiple above while having low or negative ROIC (meaning the business destroys economic value even at its current size) — genuinely "cheap for a very good reason," not a bargain.
- **Recommended usage:** compare ROIC against the company's own estimated **cost of capital (WACC)** — `ROIC > WACC` signals genuine value creation (a real positive signal for the fair-value estimate's credibility); `ROIC < WACC` should suppress/discount the confidence of any "cheap" fair-value signal derived from the multiples above, exactly the same structural role `optionsAnomalyConfidence.js`'s OI-confirmation adjustment plays for the Options Agent (a corroborating/discounting gate on top of a headline number, not a replacement for it).
- **WACC itself is a real estimation challenge** (requires cost of equity via CAPM — risk-free rate, beta, equity risk premium — and cost of debt, weighted by capital structure) — recommend using a **sector-average WACC proxy** (per the Damodaran dataset discussed in §10) rather than attempting a full per-company CAPM computation for an MVP, disclosed honestly as an approximation.

## 9. Sector-relative valuation

**Core principle:** an absolute multiple is only meaningful in the context of its sector's structural norms — a bank's P/B of 1.2 and a software company's P/B of 8 are not on the same "cheap-to-expensive" scale, since asset-heavy vs. asset-light business models produce structurally different "normal" multiples. Every multiple in §2-7 above should be computed **both** in absolute terms and **relative to the company's own sector/industry peer group** (e.g., expressed as a percentile rank or a z-score against the peer distribution), reusing `finnhubIndustry` (already live in this codebase, per §1) as the grouping key rather than introducing a new classification system.

- **Peer-group construction options**, in order of increasing complexity: (a) simplest — this platform's own already-tracked universe of symbols grouped by `finnhubIndustry` (cheap, but limited to symbols this platform already tracks, so peer-group size may be small for niche industries — a real, disclosed confidence constraint, see `VALUATION_SCORING_MODEL.md`); (b) a broader, externally-sourced industry-average dataset (the Damodaran NYU Stern dataset, described in §10, is the standard free academic source specifically for this exact purpose — industry-average multiples, margins, growth, and cost-of-capital figures, refreshed periodically); (c) a live, paid peer-group API from a professional-tier vendor.
- **Recommendation:** start with (a) for MVP (zero incremental cost, reuses existing data), layer in (b) — the Damodaran dataset — as a free, credible supplement specifically to solve the small-peer-group problem for niche sectors, and only consider (c) once real production scale/coverage requirements justify it.

## 10. Recommended data sources — MVP vs. Production

| Need | MVP recommendation | Production recommendation |
|---|---|---|
| Trailing fundamentals (EPS, revenue, book value, cash flow, debt, cash) | **Audit and fully utilize the response this codebase's `finnhubService.js` is already calling** (`/stock/metric?metric=all`) — the cheapest possible first step, since the API call and key already exist; confirm the exact field list against Finnhub's current docs before relying on any specific field name | A dedicated fundamentals vendor with a documented, versioned schema and SLA (e.g. Financial Modeling Prep, Intrinio, or continuing with a paid Finnhub tier) once reliance on an ad-hoc "audit what's already there" approach becomes a scaling risk |
| Forward estimates (Forward EPS, consensus growth rate, for §3/§4) | **SEC EDGAR's free, no-auth XBRL APIs cannot provide this** (filed financials are inherently historical/trailing, not forward estimates) — confirmed live this session: `data.sec.gov/api/xbrl/companyfacts/CIK##########.json` and `data.sec.gov/api/xbrl/frames/...` are real, free, no-authentication-required, updated in real time as filings are disseminated, and are an excellent *trailing*-data source, but forward consensus estimates are fundamentally a licensed, analyst-sourced product with no free equivalent, exactly analogous to `OPTIONS_DATA_RESEARCH.md`'s finding that trade-level options flow has no free equivalent. Recommend Alpha Vantage's `OVERVIEW` function (already half-wired in this codebase, per §1) as the cheapest path to a real forward-estimate field, pending field-list re-verification | A dedicated estimates vendor (e.g. Financial Modeling Prep's analyst-estimates endpoints, Zacks, or Visible Alpha/FactSet-tier data for genuinely institutional-grade estimate dispersion) |
| Raw historical financial statements (as a free, official cross-check / fallback) | **SEC EDGAR XBRL Frames/CompanyFacts API — confirmed live, genuinely free, no API key required, official/authoritative (the filed source of truth every other vendor ultimately derives from)** | Same — this is a legitimate permanent, free, official cross-check source at every tier, not just an MVP stopgap; recommend keeping it wired in permanently as a validation/fallback layer even after a paid vendor is chosen, since it can catch vendor data errors against the authoritative filed source |
| Sector/industry peer-group multiples and cost-of-capital proxies | **Damodaran NYU Stern dataset** (a well-established, free, periodically-refreshed academic dataset of industry-average multiples, margins, growth rates, and costs of capital by sector — widely used in professional equity research and valuation coursework; **not independently re-verified live this session**, a direct fetch attempt failed — confirm the current page/download structure before relying on it, as academic sites reorganize occasionally) | A live, paid peer-comparison API, or a self-maintained peer-group table built from whatever production fundamentals vendor is chosen (§10 row 1) |
| Sector/industry classification (grouping key) | **`finnhubIndustry`, already live in this codebase** | Same, or a formal GICS mapping if cross-vendor consistency ever becomes a requirement |

### Explicit MVP-vs-Production cost framing

Unlike the Options Agent (where even an MVP required a real paid vendor, since no free trade-level data exists at all), **the Valuation Agent's MVP can be built almost entirely on data this platform is already paying for and partially using (Finnhub) plus a genuinely free, official, live-verified government source (SEC EDGAR XBRL)** — the one real gap requiring a decision is forward consensus estimates (§3/§4), where Alpha Vantage's already-half-wired `OVERVIEW` function is the cheapest first attempt, with a dedicated estimates vendor as the production-scale fallback if Alpha Vantage's forward-estimate coverage/reliability proves insufficient at real scale.
