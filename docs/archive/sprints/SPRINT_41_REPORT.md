# Sprint 41 — Committee Unification — Final Report

**Branch:** `sprint-16-live-data` (not pushed) · **Commits:** 3 · **Date:** 2026-07-21

## Mission

There must be exactly ONE Investment Committee, exactly ONE CIO, exactly ONE recommendation interpretation path. Fix the architecture — no new features, no new providers, no UI redesign.

## Audit Findings — Before This Sprint

Two independent committee systems coexisted:

| | Legacy (Sprint 16/18A) | New (Sprint 38) |
|---|---|---|
| Service | `investmentCommitteeService.js` | `intelligenceCommitteeService.js` |
| Input | Ad-hoc `context`/`intelligenceReport`/`altDataSummary` | The Evidence Matrix (10 mission-named categories) |
| Output shape | `supportingArguments/opposingArguments/expertVotes/disagreementLevel/consensusLevel/specialistObservations/synthesis` | `members[]`, `agreement`, `disagreement`, `strongestSupportingEvidence`, CIO's qualitative `confidence` enum |
| CIO | None — a `synthesis` block generated by the same OpenAI call | `chiefInvestmentOfficerService.js`, a real, separate reasoning layer over the committee's own real output |
| Wired into live recommendations? | **Yes** — the only committee `autonomousRecommendationEngine.js` called | **No** — reachable only via `/v2/committee-intelligence/*` (dev console) and Sprint 39's explainability layer |
| Reachable production callers | `autonomousRecommendationEngine.js` (every live recommendation), `committeeController.js` (`/committee/analyze`, `/committee/track-record`), **`aiController.js`** (`/ai/analyze` — a caller the original architecture docs didn't name) | `committeeIntelligenceController.js`, `decisionTraceExplainabilityService.js`, `whatIfService.js` |
| Frontend consumers | `committeeApi.js` → `useVirtualPortfolio.js`'s auto-trading gate; `RecommendationCard.jsx` (via stored `DecisionTrace.committeeDebate`); `AiAnalysisScreen.jsx` (via `/ai/analyze`, a **separate, independent rendering path** from `committeeApi.js`) | `committeeIntelligenceApi.js` → `IntelligenceConsoleScreen.jsx` (internal only) |

**Classification:**
- **Canonical (kept):** `intelligenceCommitteeService.js` + `chiefInvestmentOfficerService.js` (Sprint 38, evidence-matrix-driven) — the only implementation matching the mission's named pipeline (Providers → Evidence Matrix → Committee → CIO).
- **Obsolete (deleted):** `investmentCommitteeService.js`, `committeeController.js` (+ its `/committee/*` routes), `committeeTrackRecordService.js` (+ its JSON data file), the legacy `COMMITTEE_VOTE_TO_ACTION`/`normalizeCommitteeVoteToAction` vote-scale reconciliation in `canonicalVerdict.js`.
- **Partially connected (fully wired this sprint):** `autonomousRecommendationEngine.js` and `aiController.js` were both live production callers of the obsolete system — both now call the canonical one.
- **Dead code (deleted):** frontend `committeeApi.js`; the legacy vote-scale constants in `canonicalVerdict.js` (never reachable from the new committee, which never publishes a vote string).

## Unified Pipeline (After This Sprint)

```
Providers
    │
    ▼
Evidence Matrix (evidenceMatrixService.js)
    │
    ▼
Committee (intelligenceCommitteeService.js — THE ONE committee, 8 members)
    │
    ▼
CIO (chiefInvestmentOfficerService.js — THE ONE CIO, called from exactly one place)
    │
    ▼
Decision Trace (DecisionTrace.committeeDebate = { committee, cio }, immutable)
    │
    ▼
Recommendation Explanation (explanation.committeeDebate, Sprint 39 explainability layer)
    │
    ▼
UI (RecommendationCard.jsx, AiAnalysisScreen.jsx, IntelligenceConsoleScreen.jsx — all render the same shape)
```

Every recommendation shown to the user — `autonomousRecommendationEngine.js`'s scheduled/on-demand runs, `/ai/analyze`'s single-ticker search, the internal Intelligence Console, and Sprint 39's Explainability panel — now goes through this exact same path. No second implementation remains reachable anywhere.

`committeeTrackRecordService.js` was a genuine feature (a persisted historical accuracy log) but had exactly two callers — `committeeController.js` and `investmentCommitteeService.js` — both retired this sprint; it would have become unreachable dead code, so it was retired with them rather than left orphaned. This is flagged under Remaining Technical Debt below as a real feature loss worth rebuilding against the new committee if wanted.

## Rewired Components

- **`autonomousRecommendationEngine.js`** — `buildCommitteeDebate()` now calls `intelligenceCommitteeService.convene(symbol)`, storing `{ committee, cio }` on `DecisionTrace.committeeDebate` (same column, unified content). Uncertainty is now derived from a real numeric consensus reading (`committeeCoordinator.computeConsensusLevel`, computed off the committee's own real agreement/disagreement structure) instead of a legacy `consensusLevel` field — never an arbitrary label-to-number mapping.
- **`aiController.js`** (`/ai/analyze`) — convenes the same unified committee, exposing `analysis.committee` + `analysis.cio` instead of the legacy `committeeDebate`/`committeeTrackRecord` shape.
- **`RecommendationCard.jsx`** — renders the unified committee's real members, agreement/disagreement, and CIO thesis instead of `consensusLevel`/`expertVotes`.
- **`AiAnalysisScreen.jsx`** — same rewrite for the "AI Investment Committee" tab: per-member headline/confidence/evidence, CIO summary, "why this may be wrong," missing information — all real fields from the one committee.
- **`useVirtualPortfolio.js`** — its auto-trading gate's `majorityCommitteeVote` (parsed a legacy 6-way vote scale) was replaced with `committeeLeanPass`, which reads the unified committee's real `agreement` structure and blocks only when the committee clearly leans CONTRARY — preserving the original gate's intent ("only block on a real negative signal, never on Hold/no-clear-lean") against the new shape.

## Bugs Fixed

1. **`aiController.js` was an undocumented third production caller** of the legacy committee, missed by prior sprints' own architecture docs (which named only `autonomousRecommendationEngine.js` and `committeeController.js`) — found by this sprint's audit, now unified.
2. **`AiAnalysisScreen.jsx` had a second, independent frontend rendering path** for committee data (via `/ai/analyze`) that never went through `committeeApi.js` at all — also found by the audit and unified.
3. Dead vote-scale reconciliation code (`COMMITTEE_VOTE_TO_ACTION`) in `canonicalVerdict.js` — removed.

## Consistency — Proven

**One recommendation → one committee → one CIO → one explanation → one UI**, proven end-to-end against a real, live-generated recommendation (not a fixture): triggering `POST /v2/recommendations/run` produced a real TSLA BUY recommendation whose `explanation.committeeDebate.committee` carries all 8 real members and whose `DecisionTrace.committeeDebate` is byte-for-byte the same object — verified both via direct API inspection and rendered live on the Recommendations screen ("8 specialists · Agreement: CONTRARY," per-member confidence, the CIO's real thesis).

## Regression Tests (8 new, `backend/services/intelligenceCommittee/unification.test.js`)

- The legacy committee implementation no longer exists on disk.
- No backend source file `require()`s the retired legacy modules (whole-tree grep).
- The legacy `/committee/*` routes 404 — no duplicate execution path is reachable.
- The unified committee is reachable at exactly one route (`/v2/committee-intelligence/:symbol`).

## Remaining Technical Debt

1. **Committee accuracy tracking was retired, not rebuilt.** `committeeTrackRecordService.js`'s persisted historical accuracy log had no path to survive the unification (both its callers were the retired system). A future sprint should decide whether to rebuild an equivalent feature against the unified committee's real per-member confidence and Sprint 31's existing Outcome Intelligence grading, rather than reviving the old file-based store.
2. **The unified committee's evidence matrix still reports several categories as honestly `UNAVAILABLE`** (INSTITUTIONS, most of Macro Economist's inputs, Fear & Greed) — carried over, unchanged, from Sprints 37–40's own documented gaps. Unification did not add or remove any evidence source; it only guaranteed there's exactly one consumer of whatever evidence exists.
3. **`useVirtualPortfolio.js`'s auto-trading gate (`committeeLeanPass`) is a best-effort behavioral translation**, not a byte-for-byte migration of the old vote-scale threshold — the old system's "block only on Reduce/Sell/Strong Sell" rule has no exact equivalent in a qualitative agreement/disagreement structure. The translation preserves intent (block only on a clear negative reading) but the exact trigger conditions differ; worth a dedicated review if this legacy auto-trading simulation is kept long-term (Sprint 40's report already recommended retiring the whole legacy `PortfolioScreen`/`useVirtualPortfolio` path in favor of the server-owned engine).
4. **The Sprint 39 explainability layer's "historical vs. live" distinction is now less structurally necessary** (both sides are the same system, not two different ones) but was left functionally unchanged — a live re-convene will still differ from a historical `DecisionTrace` snapshot simply because evidence changes over time, which is correct and expected, not a duplication.

## Recommendation

The architecture now has exactly what the mission demanded: one committee, one CIO, one execution path, proven by 8 new regression tests and verified live against real generated recommendations for TSLA, NVDA, AAPL, and SPY. The audit surfaced two production call sites (`aiController.js`, `AiAnalysisScreen.jsx`) that prior sprints' own documentation had missed — both are now unified, closing the last gaps. The next sprint's highest-priority follow-up is deciding whether to rebuild committee accuracy tracking against the new system, since that capability existed before this sprint and has no direct replacement yet.
