# Sentiment Intelligence — Architecture Research

**Phase:** SENTIMENT-RESEARCH-001. Pure research — no production code was written. Grounds every recommendation in this platform's **real, current state**: `backend/services/marketSentiment/` (`marketSentimentService.js`, `marketSentimentEngine.js`, `marketSentimentRollup.js`, `marketSentimentScorers.js`, `marketSentimentDimensions.js`, `marketSentimentGovernance.js` — all real, tested, Phase AI-ENGINE-002.1) plus the orchestrator's real `sentimentAgent.js` wrapper.

**The single most important finding of this research, confirmed by direct source read of `sentimentAgent.js`'s own code comment:** *"marketSentimentService.getMarketSentiment(market) is market-wide (its parameter is a market like 'US', not a stock symbol) — there is no per-symbol sentiment engine in this codebase yet. This agent's `execute(symbol)` deliberately ignores the symbol and reports the real market-wide reading, disclosed as such."* Every one of this mission's 10 research topics (financial news sentiment about a *specific stock*, social sentiment about a *specific stock*, sentiment-price *divergence for a specific stock*, abnormal sentiment *spikes for a specific stock*) describes a genuinely new, **per-symbol** capability that does not exist today — this research is the design for that new capability, built to extend (never duplicate) the real, already-working market-wide engine's governance and infrastructure.

## 1. What already exists — read directly from source

- **A real, working market-wide sentiment engine** across 8 markets (US/Europe/China/Japan/India/Crypto/Commodities/Energy), computing 8 named dimensions, 5 of them actually implemented (`NEWS_SENTIMENT`, `AI_RECOMMENDATION_DISTRIBUTION`, `FEAR_GREED`, `VOLATILITY`, `MACRO_EVENTS`) and 3 honestly disclosed as not yet implemented (`MARKET_BREADTH`, `SECTOR_ROTATION`, `EARNINGS_TREND`, each with a real, specific, disclosed reason — e.g. *"No advance/decline or % above moving average computation exists anywhere in this codebase yet"*). This exact "disclose what's not real, never fabricate" pattern is the standard this research's own new per-symbol design must meet.
- **Real, already-enforced anti-domination governance**: `MIN_CONTRIBUTOR_BREADTH = 2` and `MAX_SINGLE_DIMENSION_WEIGHT = 0.4` (confirmed live in `marketSentimentDimensions.js`) — a dominance cap directly analogous to the Claim Intelligence Layer's own `MAX_SINGLE_EVIDENCE_WEIGHT = 0.4` (verified real in this engagement's `AI-CORE-001-REVIEW`). **This research recommends the new per-symbol design reuse this exact same disclosed cap value, not invent a different one.**
- **"Financial news sentiment," as currently computed, is not real text/NLP sentiment analysis at all.** Confirmed by direct source read of `marketSentimentScorers.js`'s `scoreNewsSentiment()`: it derives a coarse sentiment proxy from `autonomousMarketService.feed`'s **impactType mix** and **importanceScore average** — an event-classification-derived proxy, not genuine sentiment scoring of article headlines/text. This is a real, concrete gap directly relevant to §2 below.
- **Two real, already-existing source-credibility mechanisms**, layered: (1) `autonomousMarketService.sourceQualityScore()` — a static allowlist (`HIGH_QUALITY_NEWS_SOURCES = ["reuters", "bloomberg", "wall street journal", "wsj", "cnbc", "financial times", "associated press", "marketwatch"]` → 95, everything else → a flat 60 default); (2) `dynamicSourceScoringService.js`/`newsSourceScoringService.js` — a real, outcome-informed dynamic trust score (per this engagement's own prior `PLATFORM-ARCH-001` verification, genuinely wired into `autonomousRecommendationEngine.js`'s live scoring chain via `sourceCredibilityOverrides`). **This research recommends the new Sentiment Agent's own Source Quality Score (`SENTIMENT_SCORING_MODEL.md` §4) reuse this exact existing two-tier mechanism rather than building a third, parallel source-credibility system.**
- **No social sentiment source of any kind exists today** — no Twitter/X, Reddit, StockTwits, or any other social-platform integration anywhere in this codebase (confirmed via repo-wide grep, consistent with this engagement's own long-standing "14/15 stub providers" finding from earlier Sprint 37 audits). Social sentiment is a wholly new data-acquisition area, evaluated in `SENTIMENT_SOURCE_STRATEGY.md`.

## 2. Financial news sentiment (per-symbol — the new capability)

- **Required data:** article/headline text mentioning the specific symbol, with a real publication timestamp and source attribution — genuinely different, more granular data than the market-wide engine's event-classification proxy.
- **Reliability:** depends entirely on the quality of the underlying NLP sentiment classifier — a real, non-trivial build/buy decision (`SENTIMENT_SOURCE_STRATEGY.md` evaluates this directly). A lexicon-based approach (keyword/phrase polarity scoring) is cheap but historically weak on financial-domain nuance (e.g., "beats expectations" vs. "beats up" require domain-aware handling); a domain-tuned financial NLP model (e.g., FinBERT-family models, or a vendor's own pre-scored sentiment field) is materially more reliable but a real cost/build decision.
- **False-positive risks:** headline-only sentiment (without reading full article text) is a well-documented source of misclassification — sarcasm, negation ("not as bad as feared"), and headlines written to be attention-grabbing rather than literally descriptive of sentiment all commonly fool naive classifiers.
- **Scientifically defensible?** **Yes, as a statistical text-classification exercise** (sentiment analysis is a mature, decades-old NLP subfield with well-established evaluation methodology) — but the *mapping* from "this headline reads negative" to "this is meaningful information about the stock" requires real, disclosed caveats (a negative headline about a minor, already-priced-in event is not equivalent to one about material new information) — this research recommends the resulting score always disclose article count/recency/source mix alongside the polarity number, never a bare "sentiment: -0.3" with no supporting context, mirroring this whole engagement's "never a bare number without its real inputs" discipline.

## 3. Social sentiment (per-symbol — the new capability)

- **Required data:** real-time or near-real-time posts mentioning the specific symbol/ticker from social platforms (X/Twitter, Reddit, StockTwits), with author metadata (for bot-detection, §8) and engagement metrics (likes/shares/upvotes, for weighting).
- **Reliability: meaningfully lower than financial news sentiment**, and this should be disclosed explicitly, not implied to be equivalent — social posts are unedited, unverified, frequently emotionally charged, and (per §8) genuinely subject to coordinated manipulation in a way professional financial journalism is not.
- **False-positive risks:** ticker-symbol ambiguity (e.g., "$ALL" for Allstate colliding with the common word "all," a well-known real problem for cashtag-based social monitoring), meme/joke posts that a naive sentiment classifier can misread as genuine conviction, and volume-driven noise (a stock trending on social media for a reason unrelated to its fundamentals, e.g. a celebrity mention).
- **Scientifically defensible?** **The text-classification technique itself is defensible** (same NLP foundation as §2), but **the underlying signal's *predictive relationship to price* is far more contested in the academic literature than financial-news sentiment's** — some academic studies find real short-term correlation between social sentiment/volume spikes and subsequent volatility, others find it dominated by noise; this research recommends presenting social sentiment as a genuinely separate, lower-weighted, more heavily caveated signal (never blended into one undifferentiated "sentiment" number with financial news — see `SENTIMENT_SCORING_MODEL.md` §1's explicit two-tier design).

## 4. Source credibility

- **Required data:** a source-identity field on every ingested item (already present in the real news-feed data this platform already has), matched against the existing two-tier credibility mechanism (§1).
- **Reliability:** the existing static allowlist (95/60) is simple and defensible for financial news (a known, stable set of major outlets); the newer dynamic, outcome-informed scoring is more rigorous but requires real graded history to be meaningful (the same sample-size-gating discipline already established platform-wide).
- **False-positive risks:** a static allowlist can miss a genuinely high-quality but less-famous outlet (scoring it at the generic 60 default) and can over-trust a major outlet's occasional low-quality wire-service reprint — both real, disclosed, acceptable limitations of a simple allowlist approach, not silently ignored.
- **Scientifically defensible?** **Yes** — using known-outlet reputation as a credibility prior is standard practice in information-quality research; the dynamic, outcome-informed extension is directly analogous to established "source reliability" tracking used in intelligence-analysis tradecraft (a source that has been repeatedly accurate should be weighted higher going forward, a well-established, non-controversial principle).

## 5. Source diversity

- **Required data:** the set of distinct sources contributing to a given symbol's sentiment reading over the analysis window.
- **Reliability:** a real, cheap, directly-computable metric (a simple count/concentration statistic over data already collected for the other signals) — no new data acquisition required beyond what §2-4 already need.
- **False-positive risks:** a genuinely low-diversity reading (many articles, all effectively re-reporting one wire story) can look like "many sources agree" when it is really "one source, echoed" — the well-known problem of wire-service syndication inflating apparent consensus. This directly motivates §6's duplicate-content filtering as a *prerequisite* for a meaningful diversity score, not an independent, unrelated concern.
- **Scientifically defensible?** **Yes** — source-diversity/concentration metrics (e.g., a Herfindahl-style index over source shares) are standard, well-established statistical tools, already used elsewhere in this platform's own research (`TECHNICAL_SIGNAL_PRIORITY.md`'s venue-concentration index for trade fragmentation) — this research recommends reusing the same concentration-index approach here, not inventing a new one.

## 6. Sentiment velocity

- **Required data:** a real time series of sentiment readings for the symbol (not a single snapshot) — requires this new per-symbol engine to persist and query its own historical readings, the same "this engine bootstraps its own history" pattern already established for the Options Agent's volume-baseline detector.
- **Reliability:** a genuine, well-defined, directly computable rate-of-change statistic once history exists; **honestly unavailable during the bootstrap window** (the first period after this capability first launches, before enough historical readings accumulate) — the same disclosed bootstrap-honesty pattern (`insufficientBaselineHistory: true`) already proven in `optionsAnomalyConfidence.js`.
- **False-positive risks:** a single unusually active news/social day can produce an apparent "velocity spike" that is really just one large, non-recurring event rather than a genuine accelerating trend — should be cross-checked against event clustering (§7) before being reported as a standalone velocity signal.
- **Scientifically defensible?** **Yes**, as a rate-of-change statistic over a real time series — directly analogous to the momentum-family concepts already designed in `TECHNICAL_SCORING_MODEL.md` §3 (continuation vs. exhaustion momentum), applied here to sentiment instead of price.

## 7. Event clustering

- **Required data:** timestamps and (ideally) topical similarity across multiple sentiment-contributing items for the same symbol.
- **Reliability:** genuinely useful for distinguishing "one real event, discussed by many sources" from "many independent, smaller events" — but requires either real topical/semantic clustering (a non-trivial NLP task) or a simpler proxy (a tight time-window clustering of items, without true topical understanding).
- **False-positive risks:** a simple time-window proxy can conflate two genuinely unrelated events that happen to occur close together in time (e.g., an earnings report and an unrelated analyst downgrade landing the same day) — should be disclosed as a real, known limitation of the cheaper proxy approach, not silently assumed away.
- **Scientifically defensible?** **The time-window proxy is defensible as a simple, transparent heuristic**; true semantic/topical clustering is defensible as a mature NLP technique (topic modeling/document clustering) but is a materially more complex, costlier capability — recommend starting with the time-window proxy for MVP, explicitly disclosed as a simplification, with real topical clustering as a Production-tier upgrade (`SENTIMENT_SOURCE_STRATEGY.md`).

## 8. Duplicate-content filtering

- **Required data:** the same source/text data already needed for §2-3, plus a text-similarity comparison mechanism.
- **Reliability:** directly addresses §5's wire-syndication problem — a real, well-established technique (e.g., a similarity threshold over normalized/hashed text, or simpler heuristics like matching headline+source-attribution patterns for known syndication relationships) can meaningfully reduce the "one story counted N times" inflation risk.
- **False-positive risks:** an overly aggressive similarity threshold risks merging two genuinely distinct but topically-related articles (e.g., two different outlets' independent coverage of the same real event, which is legitimate corroboration, not duplication) — the threshold-setting decision is a real, disclosed judgment call, not an exact science, and should be stated as such.
- **Scientifically defensible?** **Yes** — near-duplicate/text-similarity detection is a mature, well-established information-retrieval technique; the specific threshold tuning is a disclosed engineering judgment, not a scientific claim in itself.

## 9. Bot/manipulation risk

- **Required data:** for social sentiment specifically (§3) — account-level metadata (account age, posting frequency/velocity, follower/following ratios) where a social-data vendor exposes it; for financial news, cross-referencing against the credibility mechanism (§4) already substantially covers this concern, since coordinated manipulation of *major, reputable* financial news outlets is a categorically different, much rarer risk than coordinated social-media posting.
- **Reliability: the single least scientifically mature area of this whole research.** Bot-detection is a genuinely hard, actively-researched problem even for social platforms' own internal trust-and-safety teams, who have access to far more signal (IP/device fingerprinting, full behavioral history) than any third-party sentiment consumer ever will.
- **False-positive risks:** the highest of any signal in this research — a real, legitimate account posting in an unusual pattern (e.g., a genuinely engaged retail investor who posts frequently) can resemble a bot-detection heuristic's positive case; conversely, a well-disguised coordinated campaign can evade simple heuristics entirely.
- **Scientifically defensible?** **Only very weakly, from third-party sentiment-consumer data alone.** This research recommends this be the **lowest-confidence-ceiling signal in the whole Sentiment scoring model** (directly mirroring `ALGORITHMIC_ACTIVITY_SCORING.md`'s treatment of momentum ignition — a real, documented phenomenon, but one this platform cannot rigorously detect from the data it can realistically access) — presented only as a disclosed, heavily-caveated risk flag (e.g., *"unusually concentrated posting activity detected — may indicate coordinated activity, cannot be confirmed from available data"*), never as a confident, standalone "manipulation detected" claim.

## 10. Sentiment-price divergence

- **Required data:** the new per-symbol sentiment time series (§6) plus the symbol's own real price/return data (already live via this platform's existing price-history infrastructure, reused directly, not re-fetched).
- **Reliability:** a real, well-defined statistical comparison (does sentiment direction/magnitude diverge from concurrent price action) once both time series exist — genuinely useful as a "the crowd's mood and the tape disagree" signal.
- **False-positive risks:** sentiment is often a **lagging**, not leading, indicator of price (news coverage frequently follows, rather than predicts, a price move) — a naive divergence calculation risks misreading normal reporting lag as a meaningful "divergence" signal; recommend an explicit lag-window consideration (comparing sentiment against price with a modest time offset, not strictly contemporaneous) before treating a mismatch as informative.
- **Scientifically defensible?** **Yes, as a described statistical relationship** (sentiment-vs-return divergence is a real, studied concept in behavioral-finance/market-microstructure literature) **but the *causal* interpretation (does divergence predict a coming price move, or just describe a lag) is genuinely contested and should not be overstated** — recommend this signal always be presented descriptively ("sentiment and price currently disagree"), never predictively ("price will likely follow sentiment"), consistent with this whole engagement's governance against emitting anything that reads as a forward-looking verdict.

## 11. Abnormal sentiment spikes

- **Required data:** the same per-symbol sentiment time series (§6) plus a real historical baseline for that specific symbol.
- **Reliability:** directly analogous to the Options Agent's own volume-vs-baseline detector (`OPTIONS_AGENT_ARCHITECTURE.md` §5a) — a real, well-defined statistic (today's sentiment volume/intensity as a multiple of the symbol's own trailing baseline) once history exists, honestly unavailable during the bootstrap window.
- **False-positive risks:** a genuine, scheduled event (earnings, a product launch) predictably produces a sentiment spike — this is expected, not anomalous, and should be cross-referenced against this platform's existing earnings-calendar data (reusing `earningsProvider.js`, not building a second calendar) before being labeled "abnormal," directly mirroring `OPTIONS_SCORING_MODEL.md` §4's own "earnings-window re-labeling" false-positive guard.
- **Scientifically defensible?** **Yes** — a volume-vs-own-baseline anomaly statistic is the same well-established statistical approach already used and credited elsewhere in this platform's own research (Options Agent, Algorithmic Activity Agent) — this research recommends applying the identical method to sentiment volume/intensity, not inventing a new one.

---

## 12. Summary of concrete, evidence-grounded findings driving this research's design

1. Today's real Sentiment Agent is honestly, explicitly market-wide, not symbol-specific — the headline finding motivating this entire research (a genuinely new per-symbol capability, not an extension of an existing one).
2. "Financial news sentiment" today is an event-classification proxy, not real NLP text sentiment — real NLP sentiment analysis is the new capability this research designs toward.
3. Reuse the platform's own real, existing dominance-cap value (`MAX_SINGLE_DIMENSION_WEIGHT = 0.4`) and two-tier source-credibility mechanism (static allowlist + dynamic outcome-informed scoring) rather than inventing parallel ones.
4. Social sentiment and bot/manipulation-risk detection are the two least scientifically mature areas in this whole research — both should carry the lowest confidence ceilings and the most prominent disclaimers.
5. Duplicate-content filtering is a prerequisite for a meaningful source-diversity score, not an independent concern — wire-syndication inflation is a real, well-documented risk this platform must guard against.
6. Sentiment-price divergence and abnormal-sentiment-spike detection should both reuse this platform's own already-established baseline/lag-aware statistical methodology (from the Options and Algorithmic Activity research) rather than inventing new statistical approaches specific to sentiment.
