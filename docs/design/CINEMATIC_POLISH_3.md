## Headline finding: a real, systemic, codebase-wide motion gap — found and fixed

Direct inspection of `frontend/src/styles/components.css` (the real, shared NOVA component stylesheet every migrated Workspace screen's cards/buttons/toggles draw from) found that **`.nova-button`, `.nova-card`, `.nova-toggle`, and `.nova-toggle__thumb` all declare a `transition-property` list but never pair it with a `transition-duration`/`transition-timing-function`** — meaning every hover-lift, color change, and toggle-slide across the entire shared component library snaps instantly with zero eased motion, rather than animating. `frontend/src/styles/motion.css`'s own header comment states the intended rule explicitly ("No component should ever write a raw `transition-duration`... every real duration/curve is one of the tokens.css `--nova-motion-*` custom properties") — a rule these four rules silently violated by omission. By contrast, Flagship's own bespoke CSS (`workspace3d.css`'s `.workspace3d-toolbar__button`) correctly sets `transition: background var(--nova-motion-duration-standard) var(--nova-motion-curve-hover), transform var(--nova-motion-duration-standard) var(--nova-motion-curve-hover);` — this is a direct, measurable, root-cause explanation for why Flagship feels more fluid/premium than the Workspace screens built from the shared component library, even though both now reference identical design tokens.

**Fix applied**: added `transition-duration: var(--nova-motion-duration-standard); transition-timing-function: var(--nova-motion-curve-hover);` to all four rules — the exact reference values Flagship's own toolbar button already uses. This is a pure "make the already-declared transition actually animate" fix: no new visual concept, no color/spacing/layout change, and it reaches every migrated screen automatically since `IntelligenceCard.jsx` and `HeroCard.jsx` (used throughout Mission Control, Portfolio Workspace, and every other Workspace screen) both compose on top of the same `Card.jsx` → `.nova-card`.

**Verification**: full frontend regression **615/615 passing, zero regressions**. Production build clean (pre-existing chunk-size/dynamic-import warnings unrelated). No JSX/component files were touched — the fix is entirely CSS-value-level.

## The one governing principle this phase applied throughout

Flagship is a translucent floating panel over a live 3D scene; the Workspace screens are solid-surface pages on a normal background. "Indistinguishable from Flagship" cannot honestly mean "apply Flagship's exact glass/shadow treatment to every card" — that would mean giving every Workspace screen glass surfaces, which directly contradicts this codebase's own already-ratified, already-audited rule (`NOVA_DESIGN_BIBLE.md`, re-confirmed in the prior `DESIGN-PERFECTION-001` phase) that glass is Level-3-only (modals/drawers), never a default card treatment — over-applying it would itself be a redesign and a regression of a deliberate, already-reasoned decision. The correct reading of this mission, applied throughout: match the *quality and consistency of execution* (does every interactive element ease the same way, does every empty/loading/error state carry the same rigor, does typography follow the same rhythm) without matching the *specific material* Flagship uses for a different structural reason. Every finding below is judged against that standard.
